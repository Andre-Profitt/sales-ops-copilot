## Headline findings (cumulative)

### Production routes (disambiguation)

Two libs ship in this repo against think-cell. They are NOT interchangeable —
pick the right one or the factory will break in subtle ways.

- `libs/tcrender/` — **PRODUCTION ROUTE** for the LAND deck factory. Mac-side
  wrapper around `ppttc.exe <input.ppttc> -o <output.pptx>` (think-cell's
  documented headless render CLI) executed on the Windows VM over SSH. The
  9-director SD-monthly cadence runs through this lib end-to-end at ~3s per
  deck. Pairs with `scripts/build_ppttc.py` (input emitter) and
  `scripts/build_ppttc_demo.py` (canonical invocation sample). No PowerPoint
  UI, no COM, vendor-sanctioned.
- `libs/tc_com_driver/` — **UTILITY / RESEARCH ROUTE**. pywin32 wrapper
  around the 25 documented think-cell COM dispatch methods (19 PpAddIn +
  3 XlAddIn + 3 UpdateBatch). Use for bespoke chart updates
  (`UpdateBatch.AddRangeData`), interactive PowerPoint sessions,
  `PresentationFromTemplate` flows, and COM probes against the live add-in.
  Smoke-verified on the VM but NOT the bulk-render path. Not deprecated —
  it covers a different use case.

Rule of thumb: if you're rendering a `.ppttc` to a bound `.pptx` in batch,
use `tcrender`. If you're driving an open PowerPoint instance method-by-method
or doing one-off COM probes, use `tc_com_driver`.

Source corpus: 9 official think-cell HTML docs in `_windows_test/official-en-*.html` (13,524 words total). Extraction at `state/thinkcell_bridge/official_docs_corpus/<ts>/extraction.json`. The five open factory-automation questions are now resolved:

- **A. `.ppttc` JSON schema (canonical)** — One canonical schema file: `ppttc/ppttc-schema.json` shipped INSIDE the think-cell installation, alongside `ppttc/template.pptx` + `ppttc/sample.ppttc` ([official-en-jsondataautomation.html#json-schema-example-files]). Top level = ARRAY of template-objects; each entry = one template copy in slide order. Each template-object MUST have exactly two keys: `template` (string path or HTTP/HTTPS URL) and `data` (array of `{name, table}` objects). Cell data types: `string`, `number`, `date` (`YYYY-MM-DD` ISO 8601), `percentage` (no `%` sign, dot decimal), `fill` (hex or `rgb(...)` added to a number/string cell), and `null`. Text-field/Harvey-ball/checkbox `table` = single sub-array with single typed object; chart/table `table` = 2D rows. Chart first row = leading `null` + category labels. Empty row `[]` is SEMANTIC — shifts color-scheme assignment. **No render-mode flags inside the JSON itself**; SaveAs path is set in the renderer call (`tcXlAddIn.SaveAs(...)` in COM, or `-o` flag for `ppttc.exe`), NOT in the .ppttc body. (Source: `official-en-jsondataautomation.html` §json-schema-example-files / §sect_json-elements / §sect_json-cell-data-types / §sect_first-rows / §sect_empty-rows / §sect_json-command-line.)

- **B. Excel-named-ranges vs `.ppttc` `name` binding** — They are NOT the same surface. The `.ppttc` `name` key refers to the **`AddRangeData Name`** field on the PowerPoint TEMPLATE element, registered via the element's mini toolbar inside PowerPoint ([official-en-introductionautomation.html#sect_report-automation-templates]). It is think-cell template metadata embedded in the chart/table/Harvey-ball/checkbox/automation-text-field, NOT an Excel workbook-level Name. **That is exactly why `openpyxl` reports 0 named ranges on `Jesper-Tyrer-land.xlsx` — by design, there are none.** The 42 names like `S01_DirectorName` live in the `.pptx` template's element metadata, the `.ppttc` references them, and the workbook is decoupled. Names are **case-insensitive**; two elements with the same name receive the same data. `PresentationFromTemplate` uses Excel LINKS (cell-range references stored in chart definitions) — also separate from Excel's Name Manager.

- **C. `Presentations.Open(.ppttc)` expected behavior** — There is **no documented PowerPoint-COM `Presentations.Open(.ppttc)` entry point**. Documented render paths ([official-en-jsondataautomation.html#sect_jsoncreatepresentation]):
  1. Double-click in File Explorer/Finder — installer registers `.ppttc` with think-cell.
  2. CLI: `ppttc.exe <input.ppttc> -o <output.pptx>` (Windows-only; `ppttc.exe` lives in `<install>/ppttc/`).
  3. HTTP POST to `tcserver.exe` with media type `application/vnd.think-cell.ppttc+json` — server returns the `.pptx`.
  4. For Excel-LINKED templates only, `tcXlAddIn.PresentationFromTemplate(...)` returns a `PowerPoint.Presentation` object via COM.
     No flag suppresses PowerPoint UI in (1)/(2). `tcserver.exe` HTTP POST is the only documented headless path.

- **D. `UpdateChart` / `UpdateBatch` / `PresentationFromTemplate` semantics** — Three distinct surfaces ([official-en-exceldataautomation.html#sect_introduction-excel-automation], [official-en-api.html#sect_apireference]):
  - `PresentationFromTemplate` — creates a NEW deck from a template whose elements are **Excel-LINKED**. Refreshed elements get their Excel links DELIBERATELY broken to prevent accidental re-pull; un-refreshed elements keep their links (so chained `PresentationFromTemplate` runs across multiple workbooks work by re-using the output as the next template).
  - `UpdateBatch` — updates SPECIFIC named elements (regardless of Excel link); `AddRangeData` (with `Transposed` flag) and `AddRangeImage` are the two scheduling primitives. Replaces deprecated `UpdateChart`. New table-image features and faster execution on large decks are `UpdateBatch`-only.
  - `UpdateChart` — DEPRECATED but still functional. Slow on large decks; lacks `AddRangeImage`.
  - `.ppttc` is a fourth, file-based surface that keys on the same AddRangeData Name. **Composability:** the docs DO support `PresentationFromTemplate` followed by `UpdateBatch`, provided the elements have AddRangeData names.

- **E. Element naming convention** — The name is set IN THE POWERPOINT TEMPLATE via the element's mini-toolbar field `AddRangeData Name` (and `AddRangeImage Name` for Excel-only table images). NOT registered in a separate file, NOT in Excel, NOT in the `.ppttc` — the `.ppttc` only REFERENCES the name. Same name applies to charts, tables, Harvey balls, checkboxes, and automation text fields (the `<<>>`-style two-angle-bracket placeholder inserted via Insert > Elements > Automation Text Field). Names are case-insensitive. (Source: `official-en-introductionautomation.html#sect_report-automation-templates`, `official-en-exceldataautomation.html#sect_updatebatch-description`.)

**Open questions the docs DO NOT answer:**

- Whether `tcserver.exe` accepts a `.ppttc` that itself omits `template` (remote template via URL is documented; in-memory template upload is NOT).
- Whether AddRangeData Name length / character constraints are bounded (no character-set or max-length spec in the docs).
- Whether `SaveAs` paths in `PresentationFromTemplate` accept UNC / network paths (only local-file examples shown).
- Whether `ppttc.exe` exposes a headless / no-UI flag — only `-o` is documented.
- How `tcserver.exe` authenticates POST requests (no auth section in these docs; the cloud-side BCrypt+HMAC scheme remains unrelated to the on-prem server flow).
